SAFAR IMPLEMENTATION STATUS — 2 October 2026

Technology: TypeScript / NestJS, Prisma, PostgreSQL target database.
The existing SQLite database remains active and unchanged.

Completed in this implementation:
- PostgreSQL adapter selection, target schema, versioned initial migration,
  prepare/generate/deploy commands and cutover checklist.
- Production startup rejects a SQLite database configuration.
- Shared date validation and reservation overlap rules used by booking and search.
- Date-based search excludes confirmed/active overlapping trips, unexpired holds,
  and vehicles whose RC, insurance or PUC expires before the requested return.
- Homepage search passes dates/city to results; results preserve dates in car links
  and login return links; booking fields prefill from the selected dates.
- Correct button CSS specificity; orange primary and outlined secondary actions.
- KYC panel/checkbox styling, progress display, expiry-aware personal statuses,
  latest-document retrieval action and collapsible attempt history.
- Updated upload/image dependencies and added isolated-database availability tests.

4. Turnaround buffers, automatic maintenance reminders and extensions.
5. Payment gateway, deposits, refunds, webhooks, settlements and invoice reconciliation.

9. Resolve remaining dependency advisories with reviewed upgrades and regression tests.
10. PostgreSQL concurrency tests and authenticated end-to-end KYC/host/payment tests.

Validation does not establish production readiness. No live identity verification,
payment, cloud provisioning or real booking was initiated during this change.

Rental operations update — 2 October 2026
- Added owner-controlled date blocks and release, audited and checked in search,
  quotes and booking creation. Existing reservations cannot be displaced.
- Server-generated rental quotes now include a separate INR 2,000 deposit.
- New bookings snapshot included distance: 300 km/24 hours, prorated by duration.
- Existing bookings retain their original pricing; no deposit retroactively added.
- Pickup/return now records fuel percentage and condition notes; trip history
  shows recorded distance and excess kilometres without inventing charge rates.
- Receipts separate rental and deposit. Checkout rejects a changed quote amount.
- Backed up SQLite before additive schema changes; PostgreSQL migration included.
- 47 automated tests passed; backend build and frontend syntax checks passed.
- Running API verified: 12-hour quote includes 150 km and INR 2,000 deposit.
- Added server security headers for production, data-backed vehicle review summaries,
  Compact SUV validation parity, and honest mobile messaging for unavailable payment
  and incomplete eight-angle host photo uploads.
- Added authenticated, party-scoped rental agreements for every booking, with vehicle,
  parties, dates, charges, deposit, inspections and operating terms plus print/PDF export.
- Verified the existing administrator account in the local database; it remains
  ADMIN and is now marked verified.
- DigiLocker sync now archives the provider's original XML/PDF bytes encrypted in
  private media storage and reopens them through authorized media links. Existing
  records created before this change still require a fresh verification if the
  provider has expired their temporary file.
- Centralized rental policy configuration now covers the ₹2,000 default deposit,
  300 km per 24 hours, configurable excess-kilometre and late-return rates,
  grace period and cancellation schedule. Booking agreements display these terms.
- Added host–Safar partner agreements per vehicle and an admin settlement preview
  that calculates recorded excess kilometres and late-return charges from pickup
  and return inspections. Damage, fuel, toll, fine and cleaning deductions remain
  manual until reviewed and recorded.
- Added versioned agreement acknowledgement endpoints and audit records for both
  renter/host booking agreements and host–Safar vehicle agreements.
- Admin overview now supports server-side search/status filters and database-backed
  operational metrics; vehicle fleet cards include pricing, availability, review,
  compliance and host-agreement controls.
- Added a separate DEALER fleet role with the same scoped fleet controls as a host,
  protected account blocking for customers/partners, daily and lifetime collected
  payment metrics, and an Excel-compatible booking MIS CSV export.
- KYC evidence cards now include an explicit download action for securely archived
  originals; archived media supports attachment downloads without changing the
  supplied XML/PDF bytes.
- Role dashboards now include a customer/host/dealer/admin account summary, and
  completed trips can receive verified customer-to-vehicle ratings.
- Host and dealer payout accounts now use encrypted account-number storage with
  last-four display, admin verification controls, and a manual payout ledger with
  status/reference updates. This is an operational ledger, not an automatic bank
  payout integration.
- Pickup, return, and damage reports now require the relevant odometer/selfie/
  condition evidence and store all linked media against the inspection record.

Still required: excess-km rate, late-return policy, cancellation policy, confirmed
hourly-vs-daily pricing policy, automatic deposit settlement/refund workflow,
host-to-customer ratings, full host/dealer onboarding and bank verification,
payment gateway, secure cloud documents and deployment.
Current rental billing remains per started 24-hour day; only kilometre allowance
is prorated. No automatic damage, late-return or excess-km charges are implemented.
